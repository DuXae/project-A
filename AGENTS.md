# SDD — Spec Driven Development

Проект ведётся по методологии Spec Driven Development. Любая функциональность
сначала описывается в спеке, затем планируется, затем реализуется по задачам.

## Правила

1. **Спека первична.** Код не пишется, пока для фичи нет `specs/<feature>/spec.md`
   с критериями приёмки.
2. **Одна фича — одна папка** в `specs/` в формате `kebab-case`
   (например `specs/user-login/`).
3. **Порядок артефактов:** `spec.md` → `plan.md` → `tasks.md` → код.
4. **Трассировка.** Каждая задача в `tasks.md` ссылается на требования
   (`FR-1`, `NFR-1`), каждая реализованная задача получает ссылку на файлы и тесты.
5. **Изменение спеки** — только через явное согласование с заказчиком;
   в спеке фиксируется версия и дата изменения (раздел «История»).
6. **Definition of Done:** все критерии приёмки выполнены, тесты проходят,
   сборка/линт зелёные, `tasks.md` полностью отмечен.

## Статусы фичи

`draft` → `approved` → `in-progress` → `done`

Статус указывается в заголовке `spec.md`.

## Структура

```
specs/
  000-template/     # шаблоны, не редактировать под задачи
  <feature>/
    spec.md         # ЧТО и ЗАЧЕМ (без технических деталей)
    plan.md         # КАК (архитектура, файлы, риски)
    tasks.md        # ШАГИ (чекбоксы с трассировкой)
```
