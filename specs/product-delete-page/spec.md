# Spec: Страница удаления товаров (мягкое удаление)

**Статус:** done
**Версия:** 1.0
**Дата:** 2026-11-25
**Автор:** DuXae

## 1. Проблема

Товары можно добавлять и смотреть, но нельзя убрать. Ошибочно введённая строка
остаётся в базе навсегда и засоряет список. При этом полное стирание опасно:
если удалили не то, восстановить данные нечем.

## 2. Цель

После внедрения пользователь сможет убрать ненужный товар со страницы
`/products-delete.html` — по одному или пачкой, с подтверждением, — при этом
запись не стирается физически и её можно вернуть в БД.

## 3. Пользователи и сценарии

### Сценарий 1: Удалить одну строку
- **Дано:** на странице удаления есть список товаров
- **Когда:** пользователь нажимает «Удалить» в строке и подтверждает
- **Тогда:** строка исчезает из списка и со страницы «Все товары»,
  показывается сообщение об успехе

### Сценарий 2: Удалить пачку
- **Дано:** в списке есть несколько товаров
- **Когда:** пользователь отмечает чекбоксами несколько строк и нажимает
  «Удалить выбранные», затем подтверждает
- **Тогда:** все отмеченные записи исчезают из списка, счётчик обновляется
- **Иначе (ничего не отмечено):** кнопка неактивна, подсказка «Отметьте хотя бы одну строку»

### Сценарий 3: Отмена подтверждения
- **Дано:** пользователь нажал «Удалить»
- **Когда:** он отменяет диалог подтверждения
- **Тогда:** ничего не удаляется, список не меняется

### Сценарий 4: Запись уже удалена
- **Дано:** запись удалили в другой вкладке
- **Когда:** пользователь пытается удалить её повторно
- **Тогда:** API отвечает 404, страница показывает «Запись уже удалена» и обновляет список

### Сценарий 5: Пустой список
- **Дано:** неудалённых товаров нет
- **Когда:** пользователь открывает страницу
- **Тогда:** видит «Нечего удалять» и ссылку на форму ввода

## 4. Функциональные требования

| ID   | Требование                                                                 | Приоритет |
|------|----------------------------------------------------------------------------|-----------|
| FR-1 | Отдельная страница `/products-delete.html` со списком активных товаров       | must |
| FR-2 | В каждой строке кнопка «Удалить»                                             | must |
| FR-3 | Чекбокс в каждой строке + «выбрать все» в шапке                              | must |
| FR-4 | Кнопка «Удалить выбранные» с числом отмеченных                               | must |
| FR-5 | Подтверждение перед удалением с перечнем удаляемых товаров                   | must |
| FR-6 | Удаление мягкое: запись получает `deleted_at`, не стирается из БД            | must |
| FR-7 | Удалённые записи не показываются на страницах списка и удаления              | must |
| FR-8 | `DELETE /api/v1/products/{id}` — мягкое удаление одной записи                | must |
| FR-9 | `POST /api/v1/products/bulk-delete` — мягкое удаление пачки одной транзакцией | must |
| FR-10 | Удаление уже удалённой записи → 404, интерфейс обновляет список             | must |
| FR-11 | Счётчик «Всего: N» и навигация на всех трёх страницах                       | should |
| FR-12 | Кнопка «Обновить» для перечитывания списка                                  | could |

## 5. Нефункциональные требования

| ID    | Требование                                                             |
|-------|------------------------------------------------------------------------|
| NFR-1 | Пачка удаляется в одной транзакции: либо все, либо никто                |
| NFR-2 | Без новых зависимостей, стиль переиспользуется                          |
| NFR-3 | Список из 1000 записей отрисовывается без подвисаний                    |
| NFR-4 | Существующие тесты продолжают проходить                                  |

## 6. Критерии приёмки

- [x] AC-1 (FR-1, FR-2): `/products-delete.html` открывается, в каждой строке есть «Удалить»
- [x] AC-2 (FR-3, FR-4): выбор строк работает, кнопка показывает количество и блокируется при нуле
- [x] AC-3 (FR-5): без подтверждения удаление не выполняется
- [x] AC-4 (FR-6): после удаления строка в БД остаётся, `deleted_at` заполнен
- [x] AC-5 (FR-7): удалённая запись исчезла с `/products.html` и с `/products-delete.html`
- [x] AC-6 (FR-8, FR-9): одиночный и пачечный DELETE отвечают 204/200 и меняют БД
- [x] AC-7 (FR-10): повторное удаление → 404 + сообщение в интерфейсе
- [x] AC-8 (NFR-4): `mvnw test` зелёный, включая тесты предыдущих фич

## 7. Вне скоупа

- Восстановление удалённых записей из интерфейса (данные в БД остаются)
- Просмотр корзины удалённых
- Автоматическая очистка корзины по расписанию
- Права доступа: кто может удалять
