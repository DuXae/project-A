# Spec: Страница со списком товаров из БД

**Статус:** done
**Версия:** 1.0
**Дата:** 2026-11-25
**Автор:** DuXae

## 1. Проблема

Сохранённые товары видны только как короткий хвост из 10 записей под формой
ввода. Полного списка нет: нельзя посмотреть, что уже лежит в базе, и нет
отдельного места, на которое можно дать ссылку.

## 2. Цель

После внедрения пользователь сможет открыть отдельную страницу и увидеть все
товары, сохранённые в базе, с их идентификатором, количеством и датой
добавления, чтобы проверить результат ввода.

## 3. Пользователи и сценарии

### Сценарий 1: Просмотр списка
- **Дано:** в таблице `products` есть записи
- **Когда:** пользователь открывает страницу `/products.html`
- **Тогда:** видит таблицу со всеми записями и общим количеством

### Сценарий 2: Пустая база
- **Дано:** таблица `products` пуста
- **Когда:** пользователь открывает страницу
- **Тогда:** видит сообщение «Товаров пока нет» и ссылку на форму ввода

### Сценарий 3: Ошибка загрузки
- **Дано:** API недоступен или вернул ошибку
- **Когда:** страница пытается загрузить данные
- **Тогда:** видит понятное сообщение об ошибке и кнопку «Повторить»

### Сценарий 4: Переход между страницами
- **Дано:** пользователь на любой из двух страниц
- **Когда:** нажимает ссылку в навигации
- **Тогда:** переходит на форму ввода или на список товаров

## 4. Функциональные требования

| ID   | Требование                                                                 | Приоритет |
|------|----------------------------------------------------------------------------|-----------|
| FR-1 | Отдельная страница `/products.html` со списком товаров из БД                 | must |
| FR-2 | Столбцы: ID, Товар, Количество, Дата добавления                             | must |
| FR-3 | Показываются все записи одним списком, область прокручивается                | must |
| FR-4 | На странице видно общее количество записей                                  | must      |
| FR-5 | Пустое состояние с понятным текстом и ссылкой на форму                      | must      |
| FR-6 | Сообщение об ошибке загрузки и кнопка «Повторить»                           | must      |
| FR-7 | Навигация между формой ввода и списком на обеих страницах                   | should    |
| FR-8 | Дата отображается в читаемом локальном формате                              | must      |
| FR-9 | Данные только для чтения: нет правки и удаления                             | must      |

## 5. Нефункциональные требования

| ID    | Требование                                                          |
|-------|---------------------------------------------------------------------|
| NFR-1 | Без внешних зависимостей и CDN, стиль переиспользуется из формы      |
| NFR-2 | Все записи грузятся одним запросом: `GET /api/v1/products?size=…`    |
| NFR-3 | Список из 1000 записей не подвешивает страницу                       |
| NFR-4 | Тесты серверной части не регрессируют                                |

## 6. Критерии приёмки

- [x] AC-1 (FR-1, FR-2): `/products.html` открывается, таблица содержит 4 столбца
- [x] AC-2 (FR-3): при большом числе записей появляется прокрутка, шапка закреплена
- [x] AC-3 (FR-4): отображается «Всего: N», совпадающее с числом строк в БД
- [x] AC-4 (FR-5): на пустой базе видно «Товаров пока нет»
- [x] AC-5 (FR-6): при ошибке API видно сообщение и кнопка «Повторить»
- [x] AC-6 (FR-7): ссылки ведут на `/` и `/products.html` с обеих страниц
- [x] AC-7 (FR-8): дата показана как `дд.мм.гггг чч:мм`
- [x] AC-8 (NFR-4): `mvnw test` зелёный

## 7. Вне скоупа

- Редактирование и удаление записей
- Фильтры, поиск, сортировка по клику на заголовок
- Экспорт в CSV/Excel
- Постраничная навигация (по решению заказчика — все записи сразу)
