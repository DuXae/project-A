# Spec: Форма ввода товаров (таблица 30 строк)

**Статус:** done
**Версия:** 1.0
**Дата:** 2026-11-25
**Автор:** DuXae

## 1. Проблема

API есть, но пользоваться им можно только через curl. Нужен простой экран для
ручного ввода данных без установки дополнительных инструментов.

## 2. Цель

После внедрения пользователь сможет заполнить таблицу «Товар / Количество»
и одной кнопкой сохранить данные в PostgreSQL, чтобы не работать с API вручную.

## 3. Пользователи и сценарии

### Сценарий 1: Ввод и сохранение
- **Дано:** пользователь открыл страницу приложения
- **Когда:** заполняет несколько строк таблицы и нажимает «Сохранить»
- **Тогда:** строки сохраняются в БД, появляется сообщение об успехе,
  заполненные поля очищаются

### Сценарий 2: Ошибка валидации
- **Дано:** пользователь ввёл товар, но количество пустое или не число
- **Когда:** нажимает «Сохранить»
- **Тогда:** сохранение не происходит, ошибочная строка подсвечивается,
  выводится понятное сообщение

### Сценарий 3: Пустая форма
- **Дано:** все строки пустые
- **Когда:** пользователь нажимает «Сохранить»
- **Тогда:** запрос не отправляется, выводится подсказка «Заполните хотя бы одну строку»

## 4. Функциональные требования

| ID   | Требование                                                                 | Приоритет |
|------|----------------------------------------------------------------------------|-----------|
| FR-1 | Страница с формой по центру экрана, заголовок и таблица                       | must |
| FR-2 | Таблица ровно из 2 столбцов («Товар», «Количество») и 30 строк                | must |
| FR-3 | Область таблицы прокручивается, заголовок столбцов остаётся видимым           | must |
| FR-4 | Кнопка «Сохранить» отправляет заполненные строки в API                        | must |
| FR-5 | Данные сохраняются в PostgreSQL (новая таблица `products`)                    | must |
| FR-6 | Серверная валидация: название не пустое, количество — целое число > 0         | must |
| FR-7 | Ошибки API отображаются пользователю текстом                                  | must |
| FR-8 | После успешного сохранения заполненные строки очищаются                       | should |
| FR-9 | Список последних сохранённых записей отображается под формой                  | could |

## 5. Нефункциональные требования

| ID    | Требование                                                        |
|-------|-------------------------------------------------------------------|
| NFR-1 | Без сборки фронтенда: статические HTML/CSS/JS, отдаются Spring Boot |
| NFR-2 | Нет внешних CDN и зависимостей — работает офлайн                    |
| NFR-3 | Адаптивность: на узком экране таблица не ломает вёрстку             |
| NFR-4 | Тесты API и валидации покрывают сценарии 1–3                        |

## 6. Критерии приёмки

- [x] AC-1 (FR-1, FR-2): на `/` открывается страница, таблица имеет 2 колонки и 30 строк
- [x] AC-2 (FR-3): при заполнении 30 строк появляется вертикальная прокрутка, шапка видна
- [x] AC-3 (FR-4, FR-5): сохранение 3 строк создаёт 3 записи в `products`
- [x] AC-4 (FR-6): количество `0`, `-1`, `abc` отклоняется с HTTP 400
- [x] AC-5 (FR-7): сообщение об ошибке видно на странице
- [x] AC-6 (FR-8): после успеха поля ввода пусты
- [x] AC-7 (NFR-4): `mvnw test` зелёный

## 7. Вне скоупа

- Редактирование и удаление записей через UI
- Аутентификация, роли, разделение данных по пользователям
- Пагинация списка в UI, экспорт в Excel
- Мобильное приложение
